# 赛博炒粉 · v0.5.4 晴雨生活版

晴天、阴天与小雨随营业日和营业时钟自然变化，可在“日照与天气”中立即切换预览。天气不改变订单、经营账目和排行榜规则。街坊与室外食客雨中撑伞，雨停收伞；商铺门口已抵达的等候者与消费后停留者可在雨棚下避雨。屋顶范围遮挡雨丝，雨天街道变暗、水洼渐湿，雨停后逐渐消退，夜晚水面呈现路灯暖色光斑。

雨滴限于镜头附近固定池：电脑最多 240 条、手机最多 110 条；伞面与伞柄共享实例，不增加点光源或实时反射。暂停冻结雨滴与动作，减少动态时保留静态天气和撑伞。天气选择与日照一起保存在本机显示设置中，原有经营存档可继续读取。

居民实际回到自家门口后进入住宅；窗内按营业作息展示用餐、阅读和休息，21:06–21:54逐户入睡并熄灯。手动日照只改变明暗，不改变在家和睡眠事实。居民详情可查看当前居家状态与入睡时间。固定窗内剪影复用实例，不新增点光源。

进出住宅有短暂门口过渡；在公园实际停留且没有服务安排时，居民可坐到现有长椅休息，离开时起身继续行走。熟人寒暄时会抬手招呼；动作支持暂停与减少动态效果。原居民路线、商业交易和排行榜经营规则保持 v052，生活姿态不增加存档状态。

街坊在安全的人行区域寒暄后，若下一段同路且没有用餐、商铺服务、预约和委托冲突，可以结伴走一段。点击居民查看实际同伴、同行目的地和进行情况。居民之间的关系独立记录真实问候、共同走完路段与实际共同到场经历，展示相识、熟悉、好友及最近互动；不替代居民对炒粉店的好感。

“小镇 → 社区活动”可查看南岸广场的下午安排、参与居民与实际到场情况。居民按既有道路步行到场、停留后离开；每天 14:30 确定空闲的参加居民。实际到场后，最多两位原计划空闲的居民可能去书店，或到炒粉店用餐，不保证购买。书店按居民钱包实际付款；炒粉店按既有餐饮预算正常抵店、排队并付款。活动不直接赠送现金，商店街收款分别记账。暂停与倍速同步，手动日照不推进，提前收摊正常结束。旧存档当天保留原安排，新增社交规则从下一营业日启用，不补造历史互动。

街坊寒暄使用透明圆角气泡、细描边、柔和阴影和小尾巴，深绿文字不受昼夜光照影响。气泡出现时轻微淡入上浮，支持暂停与减少动态效果；固定复用两个池，按关系阶段预建有限短语贴图。手机横屏增大文字显示，屏幕上沿空间不足时可以向下避让。

同楼街坊在安全的人行区域相遇时，偶尔停下打个招呼：转身面对彼此，短暂停留 2–4 营业秒并显示简短问候，随后平滑继续原来的行程。每位居民每天最多一次，同时只发生一组问候；桥梁、车道、商业排队、店内服务和用餐履约中的居民不参与。

问候随经营暂停与倍速同步，手动日照不推进；停留时间计入实际个人行程，不通过瞬移追上原路线。点击居民可查看“今日街坊问候”，仅展示当天实际发生的互动，不增加炒粉店好感或虚构经营收入。旧存档当天保留原安排，下一营业日启用问候；启用居民关系后，真实问候会记录为街坊之间的互动。

居民根据生活需求、个人偏好和可用预算决定出行，每天最多一次商铺消费，没有适合的需求时继续上班、散步、用餐和回家。居民各自拥有稳定的早餐习惯、阅读和园艺偏好，以及 ¥18 / ¥24 / ¥30 的生活消费预算。购书、买花参考实际消费记录和兴趣；理发与诊所照护完成后，至少分别间隔 7 天、10 天才会再次产生对应服务需求。

居民详情新增“今日需求”，展示晨间钱包、生活消费预算、当天可用消费额、决定去的商铺或暂不购物原因。出行依据晨间记录生成，付款后不会拿剩余钱包反推当天决定。商铺成交仍需要实际步行抵达、排队和完成服务；预算不足、没有需求或未完成服务都不会生成虚构收款。旧档当前天保留原有行程，下一营业日启用需求安排，不重写历史交易。

五类商铺接入居民真实消费：面包房（¥6）购买早餐，部分居民午间饱腹会减少自然来店用餐；书店（¥12）与鲜花铺（¥10）积累阅读、园艺兴趣，产生交流话题，并影响已有熟悉居民的委托候选；理发店（¥15）与小镇诊所（¥18）排队接受服务，完成后在本日与次日分别增加 2 秒、3 秒用餐耐心。已确认的用餐预约与委托不会因早餐取消。

居民根据需求安排商铺出行，实际走到门口后等候叫号、进店接受服务，完成后才付款。每店同时服务一人，门口最多三人排队；三类商品每天各备货八件。居民初始生活钱包 ¥40，次日起每天补充最多 ¥20，余额上限 ¥200；未完成、售罄或付款能力不足时不扣钱。居民商铺收入单独日结，不计入玩家现金、炒粉店利润或排行榜资产。

点击商铺查看价格、库存、正在服务与排队的居民，以及今日实际付款；通过“小镇 → 商店街”也可进入。居民详情展示生活钱包、兴趣与最近五条消费；购书或买花后可在营业前、日结后每天交流一次，熟悉度最多三级，每级增加 3 个百分点自然来店意愿，最高总意愿 99%。兴趣不代替居民委托要求的真实炒粉消费次数与好感。

旧存档当前营业日保持原样，下一营业日启用新增规则；不补造历史消费。暂停与手动调整日照不推进交易。携带的面包袋、书和花束使用共享实例批次，复用既有 18 位居民，不增加点光源。当前在线挑战规则为 v050，历史版本成绩保留，旧挑战可转自由经营继续。

## 既有功能与历史版本说明

成长手册默认显示五阶段路线：站稳小店、稳定盈利、熟悉街坊、街坊托付、双店掌柜。阶段奖励研发点、主店精研招牌（普通招牌 +¥2）、装修券与称号，不发现金、不混入经营利润；原来的每日目标继续保留。盈利日和双店连胜要求完整营业 90 秒，旧存档从次日启用。

18 位居民拥有固定公寓与门牌，住宅窗灯对应实际在家状态。点击公寓可查看各户，点击居民可查看地址和关系。商铺按经营时钟开关橱窗并展示营业时间；超市连接玩家采购，面包房、书店、鲜花铺、理发店与诊所接入居民消费，其他商铺提供建筑信息。手动日照只调亮度，不把居民瞬移回家。动态窗灯使用两组实例批次，不增加点光源。v0.4.7 历史在线规则为 v047。

分店面板可设置独立售价和一道免费主推：科技园偏牛肉粉、午间客多；社区偏鸡蛋粉、晚餐客多；营地偏原味粉、每七天第六七天客多。推荐备货考虑偏好与主推，开门后菜单锁定。日结对比真实利润、缺货和流失并给出建议。旧分店当天保持原规则，次日启用；主动配置菜单立即启用。v0.4.6 历史在线规则为 v046。

新增每日固定的小镇事件与未来两天预告：雨天沿用雷雨停飞、普通街区到店间隔增加至 1.3 倍，并提出两份社区配送；科技园加班在 17:00–20:00 提出三份打包餐；周末集市在 10:00–16:00 提出四份打包餐。事件顾客按窗口进入既有队列，真实消耗食材和收款，无直接现金奖励。集市与玩家付费公园活动分开记账。

通过“小镇 → 小镇事件”或底部今日事件按钮查看备货、配送风险和未来安排。日结单列事件需求、已接入、已付款、实际餐费、未接入和接入后未完成；数据仅代表带事件标签的实际订单，不代表净增收入或净利润。刷新不重抽，暂停与手动日照不推进经营时间。旧档当天保持原规则，次日启用；历史在线挑战规则为 v045，旧榜单保留。

熟悉居民会提出加班热餐、邻里聚餐或河畔野餐；每天营业前最多接一份，展示预算、食材、出餐时间和截止时间。接单锁定最终餐价，真实交餐逐份收款，全部按时完成自动发放 ¥15–20 额外奖励。拒接和营业前撤销不扣好感，接单后失约只结算一次关系。已收餐费与额外奖励分别记账，日结可查看部分交付和失败原因。小镇及居民详情均可进入委托。

首版从实际消费至少 3 次、好感至少 60 的居民中产生候选；当天有具名晚餐预约的居民不重复发起委托。旧档当前天保持原样，下一营业日启用。历史在线挑战规则为 v045，旧版榜单保留。

旧存档当前营业日保留原有委托和预约安排，下一营业日启用新规则与来源账本；历史日结不推算客源。历史在线挑战规则为 v045，同版本分榜，旧版成绩保留；旧挑战可以转自由经营继续玩。经营时钟决定客流窗口，手动调整画面光照不会改变订单或刷客流。

18 位街坊拥有固定姓名与日程，分为上班族、社区居民和游客：上下班、买菜、散步、游览、用餐和夜间回家。点击街头人物查看身份、去向、下一站和当日消费结果；“小镇 → 居民生活”可查看完整名单。少量生活气泡复用现有防遮挡布局。

新开局的居民消费替换部分原有随机客流，每位居民每天最多尝试一次；价格预算、排队、制作、食材与付款沿用正常经营。居民进入顾客流程时隐藏街头分身，离店后继续日程。日程跟随营业时间，暂停和倍速同步，手动日照仅改变画面。旧存档继续可用，新开局启用居民消费。

进入游戏直接展示铺满窗口的小镇；顶部控制营业，底部边缘按钮打开订单、采购、科技、门店、成长、存档与设置。电脑按窗口比例适配，手机横屏适配安全区，竖屏也能操作。设置内可选择流畅/精细画质、声音、全屏及日照时间。

点击超市采购食材；住宅区域每完成 3 位本地客人的服务解锁一个次日预约名额，上限 3 位。炒粉店客流通过实际制作、服务与收款产生玩家收入；面包房、书店、鲜花铺、理发店与诊所由居民商家独立记账，其他商铺暂提供建筑信息，不提供玩家经营入口。

存档入口提供三个独立手动档位、导入导出及确认重开。自动档与手动档均为安全检查点，营业中读取会回到当天营业前。重开保留手动档位，正式挑战前的自由进度可从存档面板恢复。现金不足时先检查库存及可回收资产；待订单与配送结清后，资产仍不足最低营业成本则清算终局。

在线挑战使用 Cloudflare Workers + D1 服务端重放操作日志，玩家填写公开昵称；财富榜比较最高日结可回收净资产，生存榜比较完整营业天数。同版本分榜，每个玩家每榜保留最好一局。日结同步失败可重试相同请求，核验前锁定经营修改；也可退出挑战转自由经营。自由导入/读档不能作为正式成绩。匿名身份只保存在当前浏览器，丢失后不保证找回。后端地址由 online-config.json 配置，正式服务为 https://cyber-noodle-rank.dawei520lily.workers.dev，独立使用 cyber-noodle-rank 数据库。

资源控制：默认 30 帧，桌面像素比上限 1.25、手机 1；后处理和模型导出器按需加载，页面后台停止渲染并暂停营业。精细模式按需开启 45 帧光照，关闭后释放后处理缓冲。场景静态模型和 18 名路人合批，保留走路关节动作；基准视角绘制调用约减少 39.5%、三角形约减少 29.7%。这些是桌面 Chrome 测量，实体手机与 Safari 仍需实机验收。

小镇扩建：原建模地面 44×35，现为 104×80，面积从 1540 增至 8320 场景单位²，约 5.40 倍。保留原街区与配送终点，在外围增加 24 栋住宅、商铺与公共建筑，连接道路、人行道、钟楼广场、南岸喷泉、图书馆、诊所和公园。新增“小镇、北街、西街、东街、南岸”镜头，原有小店近景继续保留。

模拟时钟：准备期 07:00，营业的 90 秒对应 07:00–22:00，倍速同步推进、暂停冻结，结算保持夜晚，下一日回到早晨。日光、天空和环境光连续变化，黄昏逐渐开启 79 盏路灯模型及窗灯。远景用发光灯罩和单次实例化光池，近镜头最多 8 个实际点光源照亮物体；扩建建筑按街区合批并关闭远景建筑实时阴影，以控制开销。低端设备建议使用流畅模式。

声音：首次点击或键盘操作后播放本地合成的轻快循环 BGM，收款、采购和升级有提示音。“设置”中独立控制背景音乐和音效，记住偏好。新玩家默认开启，已有静音偏好继续保留。暂停或切到后台时音乐静音；浏览器不支持音频时仍可正常经营。无需下载外部音乐文件。

新增经营提醒：营业时显示低库存、待清空碗、待配送餐点，点击可打开对应服务面板。问题解除后提醒自动消失。日结及次日 AI 卡片根据真实经营记录提供采购、清桌和配送建议，不把缺料次数直接当成失客原因。街区人物改用与顾客相同的两节腿、脚掌补偿及接地高度计算。

一款浏览器 3D 经营游戏，经营场景中的“好好炒粉”小店，协作使用 AI 排单、机器人与无人机。所有 AI 行为均为本地游戏规则模拟，不连接外部大模型。自由经营无需联网账号；正式榜单使用匿名在线身份。

## 网页版

访问 https://xdw-h.github.io/cyber-noodle/ 即可游玩，无需安装 Node.js。支持 WebGL 2 的现代浏览器；手机可切换流畅模式。首次打开按引导备货，再开门营业。

存档只保存在当前浏览器与站点，不会自动跨设备同步。更换网址前请在“帮助”中导出 JSON，再在新网址导入。营业中刷新会恢复到当天开门前；清理站点数据会清除本地存档。发布验证采用 Chrome 桌面和移动视口，实体低端手机及 Safari 尚未实测。

点击“门店经营”，在科技园（投资 ¥600 / 日费 ¥45）、社区（¥700 / ¥35）、营地（¥800 / ¥30）三处比较选址，查看预算后确认开店。投资含基础炒粉机器人，食材另购；本版最多一家分店，确认后地点固定。建议先经营主店赚取资金，投资后仍需保留两店备货和开门费用。

分店有自己的库存、订单与两秒出餐机器人，只做现场自取。主店继续处理堂食、外卖和街区委托。两店共享现金，分别采购，缺货不能借用另一家店的食材；分店实际出餐后才收款。推荐备货参考：科技园约 16 碗、社区约 13 碗、营地约 10 碗，实际销量受需求、售价与库存影响。

在分店面板输入数量或点击“推荐备货”，再确认分店采购。统一“开门营业”前会检查两店运营费，失败不扣费。营业前可安排分店休息，休息日不收分店日费，已有生鲜仍在收摊时报废。面板打开暂停两店，关闭继续；全局暂停与倍速均同时生效。收摊只完成分店当前锅内餐，不继续制作排队订单。

日结分别列出两店收入、食材耗用、生鲜报废、运营费用、利润和采购投资，合计利润等于两店利润相加。目标与委托奖励独立计入共享现金。分店原料、选址与累计销量随存档保存，旧存档自动补齐“没有分店”。营业中刷新仍恢复到两店开门前快照。

“查看分店”切换至所选地点，可看到招牌、机器人炒粉站和自取台；点击分店可回到经营面板。

## 新增：三个街区委托与仓储经营入口

点击“街区经营”或建筑旁的地点按钮，营业前免费选择一个当日委托。科技园“午间办公餐”需要 3 份送达，奖励 ¥60 与 2 研发点；社区“邻里暖心餐”需要 2 份送达，奖励 ¥45 与 1 点；营地“河畔野餐时光”需要 2 份送达，奖励 ¥65 与 2 点。开门后锁定，接取后远程需求优先来自目标区域，达标后恢复普通分布。

只有带当日合同标识、送到正确地点的真实餐点才计入委托进度；出餐、起飞和补货不算。运输仍占用无人机并照常消耗电量、运费，迟送折扣仍然生效。可开启自动派送，委托进行时自动优先派送委托餐点；雷雨天可用地面备用配送完成任务。

完成后在街区面板或日结领取一次奖励，奖励计入独立现金收入与研发点，不增加餐食利润。未达标无额外罚款；次日重新选择委托，未领取的当日奖励不结转，累计完成数与已领奖励保留。旧存档自动补齐街区状态，营业中刷新仍恢复开店前快照。

三个目的地加入独立接餐人物、签收台、邻里行人和运输提示。送达后短暂显示餐盒与签收动作，面板记录真实签收地点、订单号和配送方式；这些表现不再次收款。中央厨房增加仓管员、出库清单与补给时移动的传送箱。厨房面板显示实际库存、补货内容、费用与运力状态，可直接呼叫补给；食材到达主店后才入库。

建议两分钟体验：备货 → 街区经营选择社区 → 开启自动派送 → 关闭面板开门 → 切换社区视角 → 送达 2 份后领奖。面板打开时暂停营业，关闭恢复。

真实 WebGL 3D 经营游戏。模型包含瓦片屋顶、木纹柜台、机器人双臂、炒锅与蒸汽、四旋翼无人机、充电台、顾客、树木和花箱。AI、机器人、无人机从第一天参与经营；保留每日目标、研发、装修、顾客偏好和招牌餐。

## 新增：街区探索与顾客用餐

默认展示一张连续的 3D 街区：中央厨房智慧仓、科技园 AI 创客中心、创客社区、江畔营地，加上主店与花园堂食区。地图包含道路、人行道、河流、两座桥、喷泉、咖啡车、货车与街边行人。顶部地点按钮或直接点击建筑可切换近景，右键拖动可平移查看。

无人机送餐终点对应三处真实停机坪；中央厨房补货从实际仓库装货坪飞来。街区里的货车与地面机器人目前是场景模型，不代表新增了一套运输经营系统。

开店后，堂食客人从街口走来，接待入座后才点单。支持单人食客、结伴双人和亲子客；双人客必须同桌安排。四桌八座可自动接待或手动选桌，允许拼桌可以切换。客人会等待、看手机、看菜单、吃粉、聊天和离店；亲子客有独立儿童模型，点击人物可查看需求。路边行人属于环境角色。

炒粉完成后，堂食餐点进入服务队列，小满机器人到柜台取餐、送到桌上才收款。落座点单后等待送餐超过 25 秒按九折结算并影响口碑。用餐后空碗占住座位，小满清桌后才能重新接待。自取顾客取餐离店，外卖依然送达回款，三种订单不会重复结算。

在“堂食接待与服务”中切换自动接待、自动清桌、允许拼桌，安排桌位、手动清桌，选择均衡 / 送餐优先 / 清桌优先。打开控制台暂停，关闭恢复。基础服务机器人免费配置，无额外日费；营业前可花 ¥220 升级 Pro，移动速度从 3.4 提高至 4.5，清桌从 4.2 秒缩短至 2.6 秒。日结单列堂食送达、收入和清桌次数。

刷新恢复到开店前快照，不保存营业中间态；旧存档自动补齐堂食配置。收摊停止接客、取消未开始制作的餐点，完成在制餐点、已出锅餐点、用餐与清桌后结算。主店与一家选址分店由玩家经营；五类商店街场所由居民商家经营，补给与配送地点沿用既有流程。

## 3D 操作

鼠标拖动旋转，滚轮缩放，右键拖动平移；手机单指旋转、双指缩放。顶部可切换全景、门店、厨房、物流视角，放大场景后按 Escape 收起。点击场景中的机器人、AI 屏幕、无人机或柜台可打开对应经营面板。右下角切换精细光照 / 流畅模式，手机默认流畅模式。

“导出模型”下载真实 GLB 场景，包含几何、材质与贴图，可导入 Blender 等工具。导出的是当前静态场景，不包含经营代码或程序动画。场景依照独立美术原型建模，原型图不是游戏截图。Three.js 0.180.0 和依赖随包附带，许可证见 vendor/LICENSE；不依赖 CDN。

## 新增成长玩法

完成每日目标：履约 12 碗奖励 ¥40 和 1 研发点；远程送达 3 份奖励 ¥50 和 1 点；餐食收入 ¥300 奖励 ¥60 和 2 点。点击目标条领取，每项每天仅一次，次日目标重新开始。未领奖励不会自动结转。

在“成长 · 装修”中使用研发点和资金研究：AI 偏好记忆为点中偏好的常客增加 1 / 2 元收入；精密传动减少 20% / 40% 磨损；快充电池使待机充电达到每秒 7% / 9%。各两级，费用依次是 2 点 + ¥120、3 点 + ¥220。仅可在营业前研究。

装修会出现在场景中：花园座椅 ¥100（现场耐心 +5 秒）、暖光招牌 ¥160（到店间隔缩短 10%）、保温柜 ¥140（外卖超时宽限 +8 秒）。每项只需购买一次，营业前布置。

四类现场顾客拥有不同偏好和耐心：学生爱鸡蛋粉、上班族和美食客偏爱牛肉粉、街坊偏爱原味。开店前可选择今日招牌，对应餐品每份收入 +¥1。AI 记忆收益只在自动策略下生效。

目标奖励计入独立现金收入，不增加餐食经营利润；研发和装修属于设备投资。升级兼容旧存档，不重置原现金或库存。

## 开始

下载仓库后，双击“启动3D小店.cmd”，保持终端开启；或在目录中运行 node server.cjs 后访问 http://127.0.0.1:4174。需要 Node.js 和支持 WebGL 2 的 Chrome / Edge；有 Codex 运行时的电脑也可由启动器识别。ES 模块需要 HTTP 服务，不能直接双击 index.html。若浏览器先打开而服务尚未就绪，刷新一次即可。服务仅监听本机。已有预览运行时直接访问上述地址，无需重复启动。端口冲突时可在 PowerShell 7 设置 $env:NOODLE_PORT = 4175，再运行启动器；浏览器会打开对应端口。

## 两分钟上手

1. 完成引导，在采购中点击“AI 预测备货”，确认采购并开门营业。
2. AI 自动排单，机器人按顾客配方制作；在 AI 中枢切换均衡、利润或耐心优先策略。
3. 打开低空物流调度，为炒好的外卖点击“无人机起飞”，或开启自动派送；关闭面板恢复飞行。
4. 缺货时从中央厨房呼叫原料包；补货和送餐共用运力，食材到达后入库。
5. 日结核对损益，次日选择机器人工作模式、保养或升级设备。

## 三项科技玩法

AI：自然语言需求识别、加料配方、备货预测、订单排序、决策日志。使用本地游戏规则模拟，没有调用外部大模型。手动模式需要玩家安排制作。

机器人：标准 2 秒、极速 1.2 秒、节能 3 秒；速度、费用和磨损不同。耐久为零后人工以 4 秒制作，花费 35 保养。Pro 升级 600，制作时间再缩短 25%。

无人机：科技园、创客社区、江畔营地三条航线；往返、电量、自动充电、运费和餐价溢价。雷雨停飞，可选 8 元 / 18 秒地面备用配送。Pro 升级 500。中央厨房提供米粉青菜包和鸡蛋牛肉包，到达才入库。

## 经营与存档

初始现金 800，基础设备由游戏孵化器提供。标准机器人小店日费 80，启用 AI 另付 12；极速 +30，节能 −10，机器人 Pro +10。配送、补货运费和保养均计入运营费用。外卖送达后才收款，超时收入打八折并影响口碑。

利润 = 收入 − 耗用食材 − 生鲜报废 − 运营费用。采购和设备支出单列现金流，不重复扣入利润。生鲜收摊清空，米粉与鸡蛋保留。营业 90 秒，收摊会完成锅中餐和待配送任务；未开始制作的订单取消。

存档仅在当前浏览器和访问地址。营业中刷新恢复到开店前快照。旧版合法存档自动补齐科技设备，保留现金、库存与经营进度。帮助中可导出 / 导入 JSON；重开前要求确认，损坏存档不会静默覆盖。

# 人物动画优化版（2026-10-27）

收碗衔接精修：伸缩托送臂跟随回收碗底，落盘后缓慢收回；气泡指示线按实际缩放后的边界裁切，从靠近人物的一侧引出。

用餐收尾：心情气泡附带人物指示线；炒粉按独食、结伴、亲子各自的用餐时长逐渐减少，起身留下空碗。机器人在原清桌时间内逐碗回收到下层托盘，返程按真实回收数量显示一碗或两碗。暂停冻结用餐和收碗，减少动态效果取消回收的装饰弧线。保留原经营计时与收益规则。

食客反馈：心情与街区签收气泡统一按屏幕位置避让，催餐、点单优先；宽度按屏幕补偿至约 100–160 像素，手机最多同时显示 2 个，桌面最多 4 个。气泡浮层避免被建筑遮挡。吃饭有夹粉、送入口与停顿，已用餐人物离店会轻微回头致意；端餐人物不挥手，减少动态效果关闭装饰动作。

进出与交餐：入口的进店、离店路线分流，双人同行间距统一为 0.55；机器人上餐在既有交餐时间内完成托送、落桌与伸缩臂回收，交餐中桌面不会重复显示餐碗。路线调整可能改变到达时间，收益与服务时间公式保持原规则。入口仍采用轻量避让，未加入完整物理碰撞系统。

动作精修：急转弯收短步幅并提高步频，头部提前看向目标；对准座位后连续落座；托盘补偿身体起伏。避让计算跳过无位移桌面检查，多人时先筛选可能接触的近邻。合成基准可见 work/crowd-bench.cjs，耗时变化不等同于整个游戏帧率变化。

追加接地与避让：两节腿反解、独立脚掌补偿、按身高计算接地高度；顾客与服务机器人附近有限错身，队伍满员时折返到接待区，避免队尾排入餐桌；端餐时收起手机。保留暂停与减少动态效果。避让为路线附近的小幅视觉侧移，密集入口仍可能短时重合。

保留双店经营。新增逐帧位置缓冲、最短角度转身、位移驱动步态、膝盖抬脚、自然摆臂和轻微身体起伏。入座与起身使用缓入缓出；端餐、看手机、吃饭姿态平滑衔接。街边行人使用有关节的人物与连续闭合路线，街区陪伴人物转身有过渡。支持暂停冻结与减少动态效果设置。
